# הכנה לבר מצווה – קריאה בתורה והפטרה

אפליקציית ווב מותאמת לנייד (Mobile-First) לתלמידי בר מצווה ולמורה, עם נתוני תלמידים ומאגר חומרי לימוד נפרדים לכל מורה.

## תכונות עיקריות

### איזון עוצמת הקלטות
- לפני העלאה מהמכשיר, ניתוח EBU R128 ו-true peak מתבצע בדפדפן המורה באמצעות `ebur128-wasm` ב-Web Worker. נשמרים נתוני מדידה ותיקון עוצמה בלבד; קובצי המקור ב-R2 אינם משתנים ואין צורך בשירות עיבוד נוסף ב-Vercel.
- במאגר, הכפתור **הפעל איזון עוצמה אוטומטי לתיקייה** סורק הקלטות שטרם נסרקו באיזון משתנה, ואז בוחר אחוזון 10 (nearest rank) של העוצמה המרבית הבטוחה של ההקלטות בתיקייה הנבחרת בלבד, לאחר האיזון המשתנה. לצד הכפתור מוצג אם הוגדר יעד לתיקייה, ואם יש בה הקלטות הממתינות לניתוח. אם סריקה או שמירתה נכשלת, היעד אינו מחושב ויש לנסות שוב; סריקות שנשמרו לא יבוצעו שוב. קבצים משותפים נספרים פעם אחת בתוך התיקייה. לכל תיקייה יעד נפרד שאינו גבוה מ-‎-18 LUFS ונשאר קבוע עד לחישוב מחדש; הקלטות חדשות יורשות אותו. כל ההקלטות המשויכות לתלמיד (כולל הפטרה וחומר כללי) מנוגנות לפי יעד התיקייה ששמה תואם לפרשת התלמיד. נתוני האבחון בכרטיסי המאגר מציגים את יעד התיקייה שבה הם נמצאים; מטא-נתוני הסריקה עצמם נשארים משותפים. לתיקייה שטרם חושב עבורה יעד נשמר היעד הגלובלי הישן אם קיים, ואחרת ‎-18 LUFS. שינוי שם תיקייה מעביר גם את היעד שלה; מחיקתה מסירה אותו. קבצים חריגים עשויים להישאר שקטים יותר. תקרת true peak היא ‎-2 dBTP וההגברה הכוללת מוגבלת ל-12 dB.
- סריקות חדשות מודדות חלונות חופפים של כ-3 שניות מדי שנייה, ומפיקות עקומת איזון עדינה: מחצית הפרש העוצמה, עד ±6 dB, ושינוי עד 1.5 dB לשנייה. חלונות ללא דיבור מספיק חזק אינם מקבלים הגברה לפי רמת הרעש שלהם. העקומה נבדקת על האודיו המפוענח כולו למדידת LUFS ו-true peak לאחר האיזון; התיקון הכולל מוגבל לפי תוצאה זו. הנגן מבצע אינטרפולציה ב-dB באמצעות אוטומציית Web Audio, ומעדכן את ציר הזמן בדילוג, חזרה ושינוי מהירות. סריקות ישנות ממשיכות להשתמש בתיקון קבוע עד לסריקה מחדש. שינוי סולם או פענוח בקצב הדגימה המקורי עלולים לשנות פסגות; אין לימיטר בזמן אמת.
- הנתונים נשמרים בנפרד ב-R2: `teachers/{teacherId}/data.json` מכיל תלמידים ושיוכים, `teachers/{teacherId}/library.json` מכיל תיקיות, פריטי מאגר ומפת יעדי עוצמה לפי תיקייה (`normalizationFolderTargets`), ו-`teachers/{teacherId}/normalization/{hash}.json` מכיל מדידות ועקומה לכל קובץ אודיו ייחודי. פריטי המאגר והשיוכים מפנים למטא-נתונים באמצעות `normalizationKey`; אין מדידות, עקומות או מפת יעדים ב-JSON של המורה. מזהה המטא-נתונים נגזר ממפתח המדיה (או זהות המקור בקובצי Drive). נתונים ישנים משובצים נקראים כרגיל ומופרדים בשמירה הבאה; ה-API מאחד אותם בזיכרון עבור הנגן ומחשב את התיקון לפי יעד התיקייה או פרשת התלמיד. קובצי מטא-נתונים ישנים אינם נמחקים אוטומטית.
- בפיתוח עם תצורת מורה מקומית, האינדקס נשמר ליד קובץ התצורה עם הסיומת `.library.json`, והמטא-נתונים בתיקייה עם הסיומת `.normalization`. גם שליפת תצורה מהאחסון מעתיקה את האינדקס ואת המטא-נתונים הנלווים.
- הקלטות מונו נמדדות כ-dual mono (תיקון של כ-3 dB), בהתאם להשמעה בשני ערוצים בדפדפן, כדי להתאים לעוצמת הקלטות סטריאו.
- הנגן מחיל GainNode לאחר שינוי הסולם. ללא שינוי סולם אין צורך בטעינת ה-AudioWorklet של הסולם; מהירות הניגון והחזרה נשארות ללא שינוי.
- הניתוח מוגבל לקובצי מונו/סטריאו עד 16MB ועד 10 דקות. לצורך הסריקה בלבד, הקובץ מפוענח ומומר ל-24kHz, עם תקציב של 128MB לדגימות המפוענחות; הקובץ המקורי ואיכות הניגון אינם משתנים. עשר דקות סטריאו ב-24kHz דורשות כ-110 MiB לדגימות. זיכרון העבודה הכולל גבוה יותר בגלל המפענח ו-WebAssembly; בנייד יש לנתח קובץ אחד בכל פעם ולהימנע מהעברת הדפדפן לרקע. קבצים החורגים ממגבלת האורך, הגודל או הזיכרון, או ללא משך ידוע, אינם מנותחים. בעת כשל ניתן לבחור במפורש להעלות ללא איזון, או לבטל ולנסות במחשב.
- במאגר חומרי הלימוד ניתן לנתח ברצף הקלטות ללא סריקת איזון משתנה בתיקייה, כולל ייבוא מ-Drive. יש להשאיר את החלונית פתוחה. כל תוצאה נשמרת מיד ומעודכנת גם בשיוכי התלמידים. כרטיס הקובץ מציג חיווי סריקה, המתנה או שגיאה; כשל ניתוח אינו עוצר את יתר הקבצים, אך כשל שמירה עוצר את התור. כאשר דגל האבחון פעיל, ניתן גם לנתח מחדש הקלטה בודדת.
- בעת ניתוח הקלטה קיימת היא מורדת למכשיר המורה. כתובת R2 ישירה חייבת לאפשר CORS עבור מקור האפליקציה (גם עבור Web Audio בניגון).
- פרטי הספרייה והרישיונות זמינים במסך אודות.
- תצוגות האבחון של העוצמה מוסתרות כברירת מחדל. להפעלתן בפיתוח מקומי או בבנייה מקומית יש להגדיר `VITE_AUDIO_GAIN_DEBUG=true` במשתנה סביבה או בקובץ `.env.local` לפני הפעלת `npm run dev` או `npm run build`. המשתנה משובץ בעת הבנייה ואין להגדירו בבניית הייצור. כאשר הוא פעיל, תוצאות הסריקה מוצגות במאגר ובניהול שיוכי התלמיד: LUFS, פסגת dBTP, תיקון dB, מכפיל העוצמה והתוצאה הצפויה. הודעות המסוף עם הקידומת `[audio-gain]` מתעדות תחילת סריקה, פענוח, תוצאות, כשל, שמירה והחלת תיקון בנגן גם ללא הדגל; נרשמים שמות הקבצים ומזהי ההקלטות, ללא כתובות המדיה או תוכן האודיו.
- כאשר דגל האבחון פעיל, בנגן פותחים את שורת **עוצמה** כדי לשנות את תיקון העוצמה הכולל (לא תוספת על התיקון האוטומטי), לראות את התיקון ברגע הנוכחי ולחזור לתוצאת הסריקה או ל-0 dB. שליטה ידנית מחליפה את העקומה בתיקון קבוע לצורכי אבחון; חזרה לתוצאת הסריקה מפעילה שוב את העקומה. הטווח הידני הוא ‎-24 עד ‎+12 dB (ומתרחב מטה אם הסריקה דורשת הנמכה גדולה יותר). השינוי זמני ומתאפס בבחירת הקלטה, בהחלפת תלמיד או בעדכון תוצאת הסריקה; אינו משנה את הקובץ או את הנתונים השמורים.
- ניתן להגביר מעבר להמלצת הסריקה, עם אזהרת מרווח פסגות/Clipping. אין לימיטר והפסגה הצפויה אינה מדידה בזמן אמת לאחר שינוי סולם או מהירות.

### 1. הזרמת הקלטות ומסמכים ישירות מ-Google Drive (ללא צורך במפתח API)
- תלמידים, הקלטות ודפי עזר נטענים מהתצורה השמורה של המורה. אין בקוד רשימת תלמידים או חומרי לימוד אישיים המשותפים לכל החשבונות, וחשבון חדש מתחיל ללא תלמידים או חומרי לימוד.
- נתיב ה-Serverless ב-[`api/drive-media.js`](api/drive-media.js) מזרים את קובצי האודיו (`.aac`, `.m4a`, `.mp3`) והמסמכים (`.pdf`, `.png`, `.jpg`) ישירות מ-Google Drive עם כותרות MIME תקינות ותמיכה ב-Range לטובת ניגון חלק בנייד (iOS Safari ו-Android Chrome).
- סנכרון חי מתיקיות ה-Drive ([`api/drive-sync.js`](api/drive-sync.js)) ומגיליון המעקב ([`api/sheet-sync.js`](api/sheet-sync.js)).

### 2. מסך תלמיד מותאם לנייד ([`src/components/StudentView.tsx`](src/components/StudentView.tsx))
- כניסה ישירה באמצעות קישור אישי לכל תלמיד (למשל `?student=boaz`).
- פתיחת מסך תלמיד, גם בתצוגה המקדימה של המורה, מתחילה בראש העמוד ואינה יורשת את מיקום הגלילה ממסך המורה. עדכוני פרטי התלמיד אינם מאפסים את הגלילה.
- הצגת **שם הפרשה**, **תאריך בר המצווה**, **מספר השבועות שנותרו עד בר המצווה** ומד התקדמות בפסוקים.
- גובה הצליל משתנה בנגן ונשמר מקומית בדפדפן בנפרד לכל תלמיד ולכל הקלטה. אין הגדרת גובה צליל כללית לתלמיד; הקלטה ללא הגדרה שמורה מתחילה ללא שינוי בגובה הצליל.
- האפשרות **הפעלה אוטומטית של הקטע הבא** נמצאת בנגן השמע במסך התלמיד וכבויה כברירת מחדל. בסיום הקלטה עוברים לעלייה הבאה לפי סדר הקריאה, או לקטע החול הבא. אחרי עליית שביעי עוברים ישירות להפטרה שהוגדרה לתלמיד, ללא ניגון חוזר של המפטיר. ללימוד מפטיר בלבד משתמשים בהקלטת מפטיר נפרדת, ובסיומה עוברים להפטרה. ללא הפטרה מוגדרת נעצרים. אם אין לקטע הבא הקלטה גלויה, מוצג הטקסט שלו והניגון נעצר ללא דילוג. בסיום ההפטרה נעצרים. ברכות וחומר כללי אינם נכללים ברצף. מצב חזרה בנגן ממשיך לחזור על ההקלטה הנוכחית.
- בתצוגת **ללא ניקוד וטעמים**, הטקסט מוצג ללא מעברי פרקים ומספרי פרקים ופסוקים, גם בעת הצצה בניקוד ובטעמים של פסוק, בתצוגת רצף ובתצוגת שורה לכל פסוק.
- 3 לשוניות ברורות ונוחות לנייד:
  1. **קריאה בתורה**: מציגה אך ורק את העליות והקטעים שהמורה הגדיר כגלויים לתלמיד.
  2. **הפטרה**: הקלטת ההפטרה של התלמיד לצד ברכות ההפטרה (לפני ואחרי) וטעמי ההפטרה.
  3. **כללי וטעמים**: הקלטות טעמי המקרא, ברכות התורה ודפי עזר (תווים לטעמים, סימני דקדוק, מלעיל ומלרע, מפיק בה"א ועוד) עם תצוגה מובנית בנייד.

### 3. מסך מורה ([`src/components/TeacherView.tsx`](src/components/TeacherView.tsx))
- מוגן בקוד מורה (ברירת מחדל: `1234`).
- כותרת המסך מציגה שתי שורות פעולות: תלמיד חדש, העלאת תוכן, בחירת נוסח ומצב השמירה בשורה הראשונה; יציאה מימין ואודות בפינה השמאלית בשורה השנייה. אורכי הקריאות מחושבים מנתוני הקריאות והנוסח, ללא טבלת ניהול אורכי הפטרות נפרדת.
- **חישובים זהים לגיליון המעקב** ([`src/utils/trackerCalculations.ts`](src/utils/trackerCalculations.ts)):
  - סה"כ פסוקים (`פסוקים בפרשה + פסוקים בהפטרה - פסוקים שנדלג`)
  - סה"כ למדנו ופסוקים שנשארו
  - שבועות לבר מצווה (`ROUNDUP(DAYS360(TODAY(), Date)/7, 0)`)
  - פסוקים לשיעור (עם התראה בצבע אדום כאשר מעל 5 פסוקים לשיעור)
  - שיעורים ללימוד ושבועות עודפים (עם התראה כאשר 2 שבועות עודפים או פחות)
  - התחלה משוערת, שבועות לימוד כולל וחודשי לימוד
- **ניהול תלמידים**: הוספת תלמיד חדש (כולל שליפה אוטומטית של מספר הפסוקים בפרשה ובהפטרה), עדכון מהיר של התקדמות בפסוקים, ושליחת קישור אישי לתלמיד בוואטסאפ או בהעתקת קישור.
- הוספת תלמיד מחולקת לשני שלבים: פרטי התלמיד, תאריך הלידה ובחירת פרשה ותאריך בר המצווה; לאחר מכן בחירת קטעי הלימוד וההפטרה, הצגת תאריך התחלה מחושב ובחירת תאריך התחלה חלופי. התאריך שנבחר נשמר בשדה `studyStartDate` ומשמש בכרטיסים, בטבלה ובגאנט; ללא בחירה נשמר החישוב הקיים. ניתן לשנות או לנקות את התאריך בעריכת פרטי התלמיד. ייבוא מ-Google Drive זמין בניהול ההקלטות לאחר יצירת התלמיד, ולא בטופס ההוספה.
- החלוניות חוסמות גלילה של העמוד ברקע ומשחזרות את מיקום הגלילה בסגירה. טופס ההוספה מוגבל לגובה המסך בנייד, עם תוכן נגלל וכפתורי ניווט גלויים.
- פסי הגלילה מוסתרים בכל האפליקציה, כולל החלוניות, הטבלאות והגאנט; ניתן להמשיך לגלול במגע, בגלגלת, במשטח מגע ובמקלדת.
- במקום מחיקת תלמיד, מעבירים אותו לארכיון. התלמיד נשאר במערך `students` בקובץ ה-JSON עם `archived: true`, כולל כל הנתונים וההקלטות. תלמידים ללא שדה זה נחשבים פעילים. לשונית **ארכיון** מציגה את כרטיסי התלמידים שבארכיון ומאפשרת לשחזר אותם לרשימה הפעילה; קישורים אישיים ממשיכים לעבוד.
- תלמידים בארכיון אינם מוצגים כברירת מחדל בכרטיסים, בטבלת המעקב ובגאנט. בגאנט ניתן לסמן **הצג גם תלמידים בארכיון** כדי לכלול אותם בטווח התאריכים, בשורות התלמידים ובחישוב העומס השבועי; הם מסומנים כ"בארכיון".
- תרשים הגאנט השבועי נפתח כשהשבוע הנוכחי ממורכז באזור השבועות, לצד עמודת פרטי התלמיד הקבועה. ניתן לגלול לשבועות קודמים ועתידיים.
- תאריכים מוצגים ומוזנים בפורמט יום/חודש/שנה (`DD/MM/YYYY`), ללא תלות בהגדרות הדפדפן. תאריכי התלמידים נשמרים בפורמט ISO (`YYYY-MM-DD`).
- בהוספת תלמיד ובעריכת פרטיו בוחרים הפטרה מרשימה נפתחת המבוססת על `src/data/verseCounts.ts`, ללא טקסט חופשי. הפרשות מסודרות לפי סדר הקריאה, ואחריהן הפטרות חגים ושבתות מיוחדות שיש להן נתוני פסוקים. מספר הפסוקים נלקח אוטומטית מהנתונים לפי נוסח אשכנז או ספרד ואינו ניתן לעריכה ידנית. בחירת הפטרה מסמנת אותה ללימוד; שינוי תבנית הלימוד אינו מחליף את ההפטרה שנבחרה. בחירת שבת מיוחדת מחליפה את המפטיר וההפטרה בהתאם.
- מצב השמירה מוצג כ"שומר...", "נשמר" או "שגיאה בשמירה", ללא פרטי ספק האחסון.
- **ניהול הקלטות ועליות לכל תלמיד**: הוספה/הסרה של נראות עליות עבור כל תלמיד, רענון תיקיית פרשה מ-Google Drive, והעלאת הקלטות חדשות לאפליקציה.
- **מאגר חומרי לימוד**: כפתור **העלאת תוכן** במסך המורה פותח חלונית לניהול תיקיות ולהעלאת הקלטות, מסמכים ותמונות, עם בחירת תיקייה, שם לתצוגה וסוג: תורה, הפטרה או כללי. נתמכים AAC, M4A, MP3, PDF, PNG, JPG, JPEG ו-WEBP. סוג החומר אינו תלוי בתיקיית האחסון.
- בניהול הקלטות תלמיד ניתן לבחור קבצים בודדים מכל תיקייה במאגר, כשברירת המחדל היא תיקיית הפרשה. רשימות הקבצים מציגות סמלים נפרדים להקלטה, למסמך ולתמונה, ואת סוג החומר לקריאה בלבד.
- סוג החומר הוא הגדרה של הקובץ, ולא הגדרה נפרדת לכל תלמיד. ניתן לשנות סוג של קובץ קיים במאגר; השינוי מעדכן את כל עותקיו ואת שיוכיו לתלמידים, ללא שינוי במזהים או בנראות. בהחלפת קובץ, כל השיוכים מקבלים את סוג הקובץ החדש.
- בחירת תיקיית השמירה והסוג נמצאת באזור העלאת הקבצים החדשים, לצד הייבוא מ-Drive וההעלאה מהמכשיר, ולא ליד בחירת קבצים קיימים.
- תלמיד רואה רק קבצים ששויכו אליו ואינם מוסתרים. אין הצגה אוטומטית של תיקיות `כללי` או `תמונות`, וגם תלמיד חדש אינו מקבל אוטומטית את כל תיקיית הפרשה. יש לשייך חומרים רצויים, כולל חומרים כלליים, במסך ניהול ההקלטות.
- העליות מסודרות מראשון עד שביעי ומפטיר, ולא לפי שם הקובץ. הסדר נשמר גם ברשימת המורה ובניווט בין הקלטות בתוך קורא הפסוקים.
- ניתן ליצור ולמחוק תיקיות, למחוק פריטים ולהחליף קובץ קיים. רשימת התיקיות מציגה רק תיקיות שנשמרו; שמות פרשות מוצעים בעת יצירת תיקייה אך אינם מחזירים תיקיות שנמחקו.
- ניתן להעביר חומר לימוד לתיקייה אחרת ולשנות שם תיקייה או שם לתצוגה של פריט. העברה שומרת על שיוכי התלמידים; שינוי שם לתצוגה מעדכן גם את העותקים המשויכים לתלמידים, ללא שינוי בקובץ המקורי או בנראות.
- בניהול הקלטות תלמיד ניתן לבחור תיקייה לשמירת קבצים חדשים מהמכשיר או מ-Google Drive. ברירת המחדל היא תיקיית הפרשה של התלמיד; אם אינה קיימת, היא נוצרת בשמירה. הקבצים נשמרים במאגר ובשיוכי התלמיד בפעולה אחת.
- במסך התלמיד ובנגן שלו מוצג רק השם לתצוגה (העלייה או התיאור), ללא שם הקובץ המקורי.
- מחיקה והחלפה דורשות אישור. החלפה מעדכנת את כל עותקי הפריט במאגר ובשיוכי התלמידים, ושומרת על מזהי הפריטים ועל הגדרות הנראות של כל עותק. קבצים ישנים שאינם בשימוש נמחקים לצמיתות מהאחסון.
- מחיקת תיקייה או פריט מסירה גם את שיוכי התלמידים ומוחקת לצמיתות את הקבצים שאינם מופיעים בתיקייה אחרת. פריט משותף נשאר זמין דרך התיקיות האחרות.
- אישור הצלחה מוצג רק לאחר השלמת השמירה ומחיקת הקבצים הנדרשת. אם המחיקה נכשלת, נשמר תור `pendingMediaDeletes` בתצורת המורה ומוצגת אפשרות "נסה שוב למחוק", גם לאחר טעינה מחדש.

## מבנה נתונים בקוד

- [`src/types.ts`](src/types.ts): טיפוסים משותפים לתלמידים, הקלטות, פרשות ונתונים מחושבים.
- [`src/data/torahReference.ts`](src/data/torahReference.ts): סדר 54 הפרשות, מספרי הפסוקים וברירות המחדל לאורכי הפטרות.
- [`src/utils/cloudSync.ts`](src/utils/cloudSync.ts): טעינה ושמירה של נתוני המורה, כולל תאימות להגדרת Google Apps Script הישנה.
- [`src/components/TeacherLibraryManager.tsx`](src/components/TeacherLibraryManager.tsx): ממשק ניהול התיקיות וחומרי הלימוד.
- [`api/library.js`](api/library.js): פעולות מאגר מאומתות, עדכון שיוכי תלמידים ומחיקה בטוחה של קבצים שאינם בשימוש.

נתוני כל מורה נשמרים ב-`teachers/<teacherId>/data.json`. רשימת `students` מספקת את התלמידים, ו-`parashaLibrary` מכיל את חומרי הלימוד לפי תיקייה. השדה `section` בחומר לימוד קובע את הלשונית (`torah`, `haftarah`, `general`); בהיעדרו, הסוג הישן `category` נשמר לצורך תאימות. בעת טעינה ושמירה, סוגי החומרים ב-`portions` מסונכרנים עם קובץ המקור במאגר לפי מזהה או מפתח אחסון, גם עבור נתונים ישנים שבהם נשמר סוג שונה לתלמיד. קבצים המשויכים ישירות לתלמיד ואינם במאגר שומרים על הסוג שלהם. מסך התלמיד, כולל תצוגת המורה המקדימה, קורא רק את `portions` של התלמיד ומכבד `visible: false`. קישור תלמיד אינו מקבל תיקיות מהמאגר. מסמכים ותמונות יכולים להשתייך לכל אחת משלוש הלשוניות.

### תצורת מורה מקומית לפיתוח ולבדיקות (Local Teacher Config)
- לצורך בדיקות וניפוי שגיאות (Debug) ללא שינוי של קובץ התצורה המתארח ב-Cloudflare R2, ניתן להגדיר ב-`.env`:
  ```env
  LOCAL_TEACHER_DATA_FILE=teacher-data.local.json
  ```
- כאשר משתנה זה מוגדר (או כאשר קיים הקובץ `teacher-data.local.json` בפיתוח), קריאות ושמירות של נתוני המורה והמאגר (`/api/r2-data`, `/api/library`) מתבצעות ישירות מול הקובץ המקומי, והקובץ המרוחק ב-R2 אינו משתנה.
- בנוסף, מחיקת פריטים במצב מקומי אינה מוחקת קובצי מדיה מ-R2 המרוחק כדי להגן על קובצי השמע והמסמכים המקוריים.
- להורדת/רענון תמונת המצב העדכנית מ-R2 אל הקובץ המקומי ניתן להריץ:
  ```bash
  npm run pull:teacher-data
  ```
- קובצי `teacher-data.local.json` ו-`*.local.json` מוחרגים ב-`.gitignore` ואינם נשמרים במאגר ה-Git.
